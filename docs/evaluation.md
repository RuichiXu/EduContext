# 评测报告

新增的两份实际业务文件结果见[2026 年 10 月 LMS 评测](business-evaluation-2026-10-12.md)。本页保留 9 月合成实验，不与新增业务结果合并。

评测日期：2026-09-14。结论：在本次合成数据小样本中，压缩输入保留了完整输入的答题质量，明显优于等估算 token 的直接截断；不能据此推断真实学校查询的准确率，也不能保证任意输入达到十倍压缩。

## 实际模型对照

数据含 120 名学生、2 个班级、6 次考试，共 720 条考试记录，原始 JSON 为 429210 字符。工具说明在各行重复，属于有意构造的高冗余数据。三个任务分别是整体报告、指定学生异常、两个班级比较。

三名独立 Codex 子 Agent 继承同一父任务默认模型及推理设置，分别只接收 raw / truncated / compressed，禁止代码代算、外部检索、读取金标或其他组答案。工具接口未暴露可核实的具体模型版本、温度、采样种子及 API 用量，所以报告不臆填这些字段。每组一次作答三题，未重复采样；raw 共享一次完整原文，另外两组接收各题对应的上下文。这不是 9 次独立生产 API 调用。

为了避免文件读取输出被截断，输入按每段最多 9000 字符连续提供到 EOF。raw 共 430153 字符、48 段；truncated 共 97893 字符、11 段；compressed 共 47633 字符、6 段。输入包包含问题及答题要求，故大于上下文本身。SHA-256 与连续区间日志验证传输完整性；三组均在各自同一个上下文窗口内完成读取。日志无法证明模型内部注意力完整性。

截断基线取每题原始 JSON 前缀，直到达到该题实际压缩结果的估算 token 数，不修复 JSON。它是简单截断基线，不代表分块、检索等更强方法；两者也没有按本次模型未知的真实 tokenizer 严格等长。三个变体使用相同问题与输出 schema。金标由原始数据独立计算，模型回答完成后逐字段评分，数值绝对容差 0.00001，数组顺序和长度必须匹配。

| 指标 | 原始完整输入 | 直接截断 | 本模块压缩 |
| --- | ---: | ---: | ---: |
| 关键事实正确 | 21/21（100%） | 3/21（14.3%） | 21/21（100%） |
| 数值字段正确 | 14/14（100%） | 0/14（0%） | 14/14（100%） |
| 数值及统计单位正确 | 16/16（100%） | 2/16（12.5%） | 16/16（100%） |
| 非空字段比例 | 100% | 14.3% | 100% |
| 全部字段正确的任务 | 3/3 | 0/3 | 3/3 |

截断组保留已知学号和统计单位，对无法确定的值回答 null。非空比例只是完成度代理，不能当作正确率。本次压缩组没有出现“原始组答对、压缩组答错”的字段，但只检查 21 个要求字段，不能证明其他信息未损失。与完整输入相比，观察到的是**质量持平、输入缩小**，并未观察到准确率提升。

最终输入、答案、金标、逐字段评分、传输日志和代码快照冻结在 [validated](../evaluation/experiments/validated/)。常用文件同步到 [artifacts](../evaluation/artifacts/)。其他实验结果均为探索资料；输入传输未经完整验证的结果标记为 `use_for_final_metrics=false`，不用于以上指标。

## 压缩规模与 tokenizer 审计

同一份原始数据，内置估算为 98698 tokens，三题目标均为 9869 tokens：

| 任务 | 压缩后字符 | 压缩后估算 tokens | 估算压缩倍数 | 原始证据行 | 达标 |
| --- | ---: | ---: | ---: | ---: | --- |
| 整体报告 | 8315 | 3286 | 30.04× | 5/720 | 是 |
| S119 异常分析 | 8723 | 3503 | 28.18× | 10/720，含 S119 全部 6 条 | 是 |
| 甲班、乙班比较 | 29227 | 15546 | 6.35× | 720/720 | 否 |

班级比较点名了两个班，因此全部记录受到保护；预算告警为 `protected_content_exceeds_budget`。不能为了十倍指标删掉被查询班级明细。

另用 tiktoken 0.14.0 的 `cl100k_base`、`o200k_base` 注入精确计数器重新压缩。它们是公开 BPE 基准，并非已确认的本次模型 tokenizer；这也不是额外模型质量实验。

| 数据/任务 | cl100k 原始→压缩 tokens | 倍数/达标 | o200k 原始→压缩 tokens | 倍数/达标 |
| --- | ---: | --- | ---: | --- |
| 整体报告 | 89326→3013 | 29.65× / 是 | 85715→2850 | 30.08× / 是 |
| 指定学生 | 89326→3227 | 27.68× / 是 | 85715→3044 | 28.16× / 是 |
| 两班比较 | 89326→14491 | 6.16× / 否 | 85715→14222 | 6.03× / 否 |
| 低冗余 1800 条 | 136773→24901 | 5.49× / 否 | 130161→24277 | 5.36× / 否 |
| 低冗余 6000 条 | 455869→45399 | 10.04× / 是 | 433841→43628 | 9.94× / 否 |

6000 条低冗余数据说明编码差异会改变临界达标结果。内置估算不能代替生产 tokenizer。原始字符数不能直接换算成模型 tokens；默认预算也不包含系统提示、其他对话与输出预留。

变动教学评语要求保留全部 1800 行时，估算仅约 1.53 倍。高基数分组可能令候选结果膨胀，此时完整返回原始 JSON，压缩倍数 1，预算失败。详细记录见 [token_audit.json](../evaluation/artifacts/token_audit.json) 和 [robustness.json](../evaluation/artifacts/robustness.json)。

## 方案取舍与消融

仅做表格、公共字段与字符串字典编码，720 条记录全量保留时，估算从 98698 降至 15483 tokens（6.37 倍），尚未达标。结合全量精确统计和任务证据选择，整体报告才降至 3286 tokens。因此不能把全部收益归因于任务理解，也不能把收益仅归因于 JSON 换格式。

采用的设计是结构去重、精确聚合、实体与异常保护、预算失败报告。它借鉴表格任务选择和紧凑序列化思路，未加载压缩模型或部署检索系统，理由与原始论文链接见 [research.md](research.md)。早期估算器对 JSON 标点计数偏高，BPE 审计发现并修正后，班级比较被正确标为未达十倍。该过程说明必须分别验证字符数、token 计数与回答质量。

## 自动化检查与复现

最终通过 38 项核心/完整性测试和 6 项评测器测试，共 44 项。其中随机测试对 120 份不同结构数据运行三种模式，共 360 组验证；检查独立 Fraction 聚合、保护行原值、目标范围、缺失与 null、异常和预算退化。另通过独立 oracle 验证和四组超过触发阈值的低冗余/高基数数据检查。以上是确定性程序验证，不属于 LLM 正确率。

本机 Python 3.14.4、Windows 11，1 千/5 千/1 万条重复元数据记录的三次热进程中位耗时约 0.13/0.64/1.28 秒，包括序列化、解析、压缩和估算计数，不包括 LLM。只是本机合成负载，未测峰值内存，也不是生产吞吐承诺。版本、检查结果和文件哈希见 [verification.json](../artifacts/verification.json)。

```powershell
python -m unittest discover -s tests -v
python -m unittest evaluation.test_runner -v
python -m evaluation.runner oracle --output evaluation/artifacts/oracle.json
python -m evaluation.robustness
python -m evaluation.collect --directory evaluation/experiments/validated --delivery-log
```

模型适配器与精确 counter 接法见 [评测说明](../evaluation/README.md)。后续应使用生产模型、独立多次调用，增加多工具重叠、长尾实体、非标准量表、开放式任务及真实业务人工审查；现有三题不能支持统计显著性或上线准确率结论。
