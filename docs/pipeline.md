# LMS 业务数据压缩完整流程

EduContext 放在 LMS 工具返回与最终回答模型之间。程序负责结构、统计与完整性，模型可选地负责从长评语中选择任务相关的原文片段，最终回答模型负责解释。此次适配不改变上游查询，也不自动补齐分页。

本文描述既有 `compress_lms`。v0.2 新增的 `compress_planned` 按“概况 → 模型或手写计划 → 校验 → 精确统计与记录证据 → 预算”执行，接入方式见[通用规划管线](planned-pipeline.md)。

## 输入与路由

调用方传入用户问题、原始 JSON、可选目标学号、来源完整性和 token 计数器。通用数据继续使用 `compress`；`data.studentList` 与 `data.activityList` 使用 `compress_lms`。前者的评语位于 `extra.stuHomeworkTeacherComment`，后者位于 `activityExtra.stuHomeworkTeacherComment`。

默认字符数严格大于 420000 才压缩。小输入原样透传；显式请求截断恢复或声明来源不完整时，即使输入较小，也把完整性状态传给下游。`force=True` 仅用于开发对照，不能据此声称线上触发了压缩。

## 解析与截断恢复

先严格解析：小数保留 Decimal，拒绝重复键、NaN、Infinity。默认遇到非法 JSON 报错。只有调用方启用 `recover_truncated=True`，才尝试识别末尾截断。

恢复保留已经闭合的完整数组元素；最后一条未完成记录整条丢弃。输入末尾的 `"score":8` 可能原本是 85，程序不会补成 8。缺少最外层括号时可保留内部已经闭合的记录，但中间缺逗号、非法转义、尾随垃圾仍然拒绝。输出记录输入哈希、恢复事件、来源不完整和“仅针对收到的完整记录”的口径。

语法有效不等于业务完整。已经由外部修复的文件，要显式传 `source_complete=False`；未知则传 `None`。模块不能恢复未收到的字节，也不能从当前行数推断全班或全部活动数量。

## 结构化记录与精确统计

LMS 适配器展开嵌套对象的叶字段，用 JSON Pointer 路径保留对应关系。数组单元格、空对象、null、缺失值与字符串数字保持区别。**全部收到的完整结构化行保留**，目标学生只决定评语保护，不是行过滤条件。

对成绩、原始 studentRate 等已声明数值字段计算数值个数、和、极值与精确分数均值；对状态字段计算原值频次。计算发生在完整收到的记录上，不让 LLM 做长表累加，也不从抽样行估计总体。不同活动的原始分数可能使用不同满分，不能把它们的算术均值直接解释为统一学习水平；studentRate 也不能改称完成率。

共享表头、公共值与重复字符串字典减少结构冗余，数值业务字段保持数值。`unpack_lms_table` 能还原保留的字段；只有未省略评语时，`restore_lms` 才允许恢复完整输入。

## 评语策略

| 模式 | 处理行为 |
| --- | --- |
| `auto` | 明确纯统计问题省略非目标长评语；指定学生问题保护其全部评语；宽泛报告或质性分析默认保留全部评语 |
| `all` | 保留所有评语原文，允许超预算 |
| `targets` | 保护目标学生原文；未命中目标时保守保留全部 |
| `none` | 显式省略其他非空评语，目标学生原文仍保护 |
| `summarize` | 显式启用模型，从非目标评语中选择原文证据；目标学生原文仍保护 |

省略数量、原始行号、缺失、null、空字符串都会进入输出。模型摘要不会因一个宽泛的“分析”问题自动启用，必须由调用方明确授权。

## 可选模型提取

HTML 评语先转换成可见文本；保留链接、图片描述、上下标等有意义信息，不执行脚本。按完整评语分批，默认每批最多 65000 字符，单条超限则失败回退，不切掉半条评语。

每批模型最多选取 5 条相关证据，兼顾优点与建议。程序检查返回行号是否完整、重复，证据是否是对应评语的连续原文子串，并记录字符位置。模型生成的概括标题可能扩大结论范围，所以最终只保留原文摘录，舍弃自由改写标题。示例、建议和宣传语仍是来源里的文字，不能转成已经实现的业务指标。

完整索引回传只能验证输入与输出的覆盖声明，不能证明模型实际理解了每一条。逐字引用只能证明出处，不能证明重要主题全部覆盖。该路径是**有损的任务相关证据选择**，不能代替逐人评语审阅，也不能据少数摘录声称“大多数学生”存在某问题。

客户端由调用方显式提供模型、HTTPS 地址和密钥，不隐式读取其他项目配置。可使用本地请求缓存减少重复调用，设置超时和调用上限。缓存含业务内容，应留在私有位置。输出截断、格式不合规或证据不匹配时最多按配置重试；仍失败则恢复该表全部评语，错误信息不携带密钥或服务商响应正文。

## 预算判断与最终回答

最终预算为 `min(config.max_tokens, original_tokens // config.ratio)`，默认 ratio 为 10。计数包含实际输出协议、数据、统计、证据与警告。模型提取成功也要重新计算最终预算；超限就返回 `within_budget=False`，不再偷偷删除受保护内容。调用方应缩小查询、分拆任务或选择合适窗口，并为系统提示、问题和回答单独预留空间。

`o200k` 与 `cl100k` 是本地公开编码对照，不是 DeepSeek 的真实 tokenizer。需要窗口硬限制时应注入对应模型的计数器，或使用服务商实际计数。

最终回答模型接收 `result.context`，遵循其中的来源范围、统计分母、原始字段含义和证据位置。对于不完整来源，答案应写“当前收到的 376 条记录”，不能写成“全班 376 人”。

## 验收顺序

先独立还原全部保留单元格，再用独立 Fraction 计算核对统计；随后检查两种公开编码预算、目标评语原文、真实文件截断恢复。最后使用同一回答模型比较原文、同预算前缀截断和压缩输入，并复核长评语证据。结果及限制见[业务评测报告](business-evaluation-2026-10-12.md)。
