# 后续改进方向与验收要求

本文是下一阶段开发要求，尚未实现的设计不能作为当前功能或当前评测结果介绍。目标是增强混合 JSON 的语义适配能力，在保留可核验事实的前提下，为下游模型构造精简上下文。

## 当前能力与下一阶段目标

| 环节 | 当前实现 | 下一阶段 |
| --- | --- | --- |
| 任务理解 | 关键词规则、实体匹配与显式配置 | LLM 生成受约束的压缩计划，程序校验后执行 |
| 结构化数据 | 精确聚合、证据保护、结构去重、预算反馈 | 通用字段映射、类型与业务口径校验，保持数值保证 |
| 自然语言 | 已适配评语按整条分批，选择有出处的片段 | 支持显式配置的多个文本字段，逐记录提取与跨记录合并 |
| 信息覆盖 | 单元格、统计、引用和索引检查 | 必保事实覆盖、长尾与冲突证据检查，人工金标召回评测 |
| 评测 | 合成数据与两份业务导出的小样本对照 | 冻结多类型任务，重复对照，区分各阶段成本与质量 |

当前没有 LLM 计划生成器、任意业务语义理解、完整事实召回保证或自动交互澄清功能。

## R1 保持独立组件边界

组件输入为用户任务、JSON 数据、可选字段说明、保护约束与预算。输出为可解释的结构化上下文和处理元数据。组件不读取报告 Skill，不理解 HTML 模板，不依赖报告章节，也不生成报告页面。

报告 Agent 在下游把压缩结果与自己的 Skill 组合，完成 HTML 生成。只有下游知道的特殊必保信息，必须通过通用的 `required_fields`、`protected_entities` 或必保事实约束传入，不能让组件猜测。上层负责给系统提示、Skill 和最终回答预留预算。

## R2 增加数据概况与计划生成

程序先提取字段路径、JSON 类型、缺失比例、记录数量、类别基数、文本长度分布以及有限格式样例。规划模型接收这些概况、用户任务和显式业务定义，不在规划阶段读取全部长评语。

样例用于理解结构，正式统计必须覆盖全部相关完整记录。规划模型不能把样例频次当作总体统计，不能依据少量样例断言某字段无关。

计划建议包括：

- 明确的信息需求、目标对象和来源范围；无法解析的时间或单位单独列出。
- 字段角色、需要的聚合或分组操作、原始记录保护条件。
- 文本字段及其处理策略：保留原文、提取证据、显式省略。
- 必保信息、预算优先级、待澄清问题和计划版本。

计划格式使用有版本的 JSON Schema。模型输出必须经过严格解析，不能成为任意 Python、SQL 或 shell 代码直接执行。

## R3 计划校验优先于执行

执行前校验字段与对象存在、类型正确、操作在允许列表内、单位与统计分母明确、预算参数合法、保护约束未被削弱。

数字 ID 与等级编码不能仅因类型为 number 就当作连续指标；来源不同或评分尺度不同的成绩不能默认合并。需求中出现排名、趋势、加权、相对时间或跨表关系时，只能执行已实现且通过测试的算子，否则显式保留或返回不支持的操作。

记录筛选与证据保护必须区分。目标保护不改变统计分母；真正筛选时输出筛选条件与筛选前后范围。对模糊任务优先使用保守计划，或返回 `needs_clarification` 给调用方。LLM 自报置信度不能作为删除业务事实的唯一依据。

## R4 推广混合 JSON 处理

支持通过字段映射接入不同业务结构，处理身份、数值、等级、状态、时间、短文本、长文本与嵌套对象。数组关系、missing/null、字符串数字、枚举编码要保持可区分。

未知字段默认保留。对于完整明细成本可接受的输入，优先保留全部结构化行；允许省略明细的任务则保留全量统计与强制证据，并声明哪些逐行关系不可还原。不得承诺所有复杂 JSON 都能压缩十倍。

## R5 改进非目标长文本处理

非目标对象仍可能贡献整体学情证据。根据任务选择相关文本，按完整记录分批，在逐记录提取后合并重复主题；记录对象、字段路径、来源位置与原文证据。

原文与提取事实必须区分，保留条件、否定、异常、少见但重要的内容和相互矛盾的证据。不要以出现频次低为由删除重要异常。目标或显式保护对象的必要原文不依赖摘要。

跨记录合并要保留来源列表。只有相关记录全覆盖、分类口径明确并经程序计算时，才能输出人数与频次；代表性摘录不能支持“大多数学生”等结论。不存在完整专家金标时，引用验证不能宣称语义完整。

文本规划、提取和审阅的重试次数、超时、最大并发与调用预算必须受控。无效计划、提取失败或超预算要有可观察的回退，不静默丢数据。当前客户端缓存包含业务内容，应继续位于私有或忽略目录。

## R6 输出协议与预算

建议保持事实、精确统计、必要明细、文本证据、字段说明、来源范围、遗漏说明和预算结果分开表达。扩展已有协议时增加版本与兼容说明，保留直接供 LLM 阅读的解码说明。

用调用方提供的计数器评估最终序列化输出。满足预算只说明尺寸合格，不代表质量合格。保护内容超预算时返回明确状态，由调用方拆任务、缩小查询或调整窗口。

## R7 质量与成本评测

冻结任务和金标后，对照原文、等预算截断、当前规则版本、新规划版本。保持最终生成模型与问题一致，记录模型、提示版本、输入哈希、计数器和实际 API usage。

验收至少覆盖：

1. 数值与统计分母准确率、对象和时间关联、必保记录覆盖；程序可确定部分要求精确一致。
2. 人工标注的关键事实召回率、无依据新增事实、否定与条件保留、罕见问题与冲突证据。
3. 模糊需求、改写表达、复合任务、未知字段、错误等级解释、截断输入和提示注入内容。
4. 压缩率、全链路输入输出 token、延迟、额外调用与重试成本；不能只报告最终回答模型节省。
5. 在报告场景中，固定下游 Skill 后比较报告事实覆盖、数字错误和幻觉；HTML 样式质量独立计分。

先建立人工金标和基线，再确定文本召回率与成本的验收阈值。新版本不能直接引用旧链路的 14/14、小样本压缩率或历史 349 条查询指标作为效果证明。

## 推荐实施顺序

1. 固定计划协议、保护约束与计划校验器，先用手写计划验证执行语义。
2. 接入可替换的 LLM 计划生成器，保留规则基线、缓存和调用上限。
3. 增加通用文本字段映射、逐记录提取、证据合并与覆盖检查。
4. 扩展冻结任务与人工关键事实集，运行配对评测后决定是否替换默认路径。

已公开的生产来源脱敏样本见 [datasets](../datasets/README.md)。数据量仍然有限，应加入额外授权样本与合成边界用例，不以单份数据验收通用语义能力。
