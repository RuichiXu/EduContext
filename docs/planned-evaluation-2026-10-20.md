# v0.2 规划管线验收报告

2026-10-20 的 v0.2 通过显式规划入口的工程发布门槛：计划校验、全量结构化记录保留、原文出处、精确统计、保护条件、失败回退和最终预算检查均有可复现验证。真实模型在冻结用例上保留 7/7 条指定事实，合成场景两次问答合计 14/14，生产大文件两次问答合计 10/10。

新入口保持 opt-in。现有 LMS 专用路径在该大文件上同样答对全部问题，且上下文更短；此次交付的主要收益是可校验的通用规划接口与字段映射，不能据此宣称优于全部既有路径。

## 验收范围与复现

验收依据为[发布门槛](acceptance-v0.2.md)。数据包括两份[生产来源脱敏样本](../datasets/README.md)、8 条合成记录及固定随机种子的 60 组结构与数值用例。合成关键事实由工程用例预先指定，包含正面发现、否定、条件、罕见异常、冲突和提示注入文本；不是独立人工专家标注集。

```text
python -m unittest discover -s tests -v
python -m unittest evaluation.test_runner -v
python -m scripts.check_public_data
python -m evaluation.planned_acceptance --output .test-tmp/planned
python -m examples.planned_integration
```

本地 97 项模块测试、6 项评测器测试全部通过；60 组随机检查包含在模块测试内，不另作独立测试数量相加。既有公开数据的 6 种变体检查通过。v0.2 安装包已构建并用于隔离导入验证。

[公开机器可读结果](../evaluation/artifacts/planned_release_20261020.json)包含输入哈希、提示哈希、代码哈希、逐题布尔检查和调用用量；不包含原始身份数据、模型缓存、凭据或完整模型答案。真实调用使用 `deepseek/deepseek-flash`，同一问题各路径重复两次，温度为 0。上下文尺寸以 `o200k_base` 计数；供应商实际 usage 另行记录，二者不是同一 tokenizer。

## 确定性检查

| 检查项 | 结果 |
| --- | --- |
| 大文件保留单元格 | 6,771 个逐项一致 |
| 小文件保留单元格 | 219 个逐项一致 |
| 精确总和、数值分母、分组 missing/null | 一致 |

| 冻结文本事实与对象、字段关联 | 7/7 |

大文件仅省略调用方允许省略的非目标评语，涉及 373 个文本单元格。小文件记录属于同一个被保护目标，所有评语都保留，因此没有文本省略。所有数值仍覆盖收到的完整记录；目标保护不改变分母。

## 真实模型配对结果

生产大文件的 5 道题固定为记录数、studentScore 总和、均值、目标学生成绩和来源完整性。金标直接来自源记录的独立 Fraction 计算与外部来源声明。源文件有 376 条收到的完整记录，不能称为完整业务总体。

| 路径 | 上下文 token | 第一次 | 第二次 |
| --- | ---: | ---: | ---: |
| 原文加来源说明 | 293,692 | 3/5 | 3/5 |
| 与新路径等预算的前缀截断 | 29,829 | 1/5 | 1/5 |
| 既有 LMS 规则路径 | 17,895 | 5/5 | 5/5 |
| 新规划路径 | 29,829 | 5/5 | 5/5 |

新路径从原文件的 293,684 token 降至 29,829 token，约 9.85 倍。计划、逐单元格遗漏说明和调用元数据也计入最终上下文，预设预算为 45,000 token。小文件从 9,112 降至 8,806 token，仅略有减少。

合成文本场景的 7 道题在四条路径中，两次均为 7/7。原文只有 224 token，新规划包装为 1,397 token；等预算截断实际保留了全部原文。因此这组测试验证条件、否定和冲突能被回答，不能用于证明压缩率或相对优势。

两次是同一冻结任务的重复调用，不能作为生产准确率估计。纯字面事实检查另行核对记录、字段与证据出处，不以问答成功替代事实覆盖。

## 调用成本与失败修复

最终轮共有 25 次逻辑调用，包括规划 6 次、文本选择 3 次、下游回答 16 次；其中 13 次命中本地缓存，12 次实际访问服务。供应商返回的最终轮实际网络 usage 合计为 141,141 token，观测网络调用时长合计约 47.84 秒。它们不是单个压缩请求的成本或端到端时延。

| 最终轮阶段 | 逻辑调用数 | usage 中的输入 token | 输出 token |
| --- | ---: | ---: | ---: |
| 规划，包括两个生产样本与三个边界问题 | 6 | 7,479 | 539 |
| 逐记录文本选择 | 3 | 813 | 61 |
| 四路重复问答 | 16 | 729,828 | 611 |

表内包含缓存复用的原请求 usage，用于看完整调用组成，不能当作本轮账单。大文件单次规划的 provider usage 为输入 2,068、输出 112 token，随后才产生下游回答成本。整个调试与验收过程共 50 次实际网络调用，usage 合计 1,024,915 token；包含失败版本和重复回归，没有只报告最终回答模型节省。

验收发现并修复了两类问题：

1. 第一版真实模型问答虽然全部通过，但漏选两个对象的正面事实，覆盖仅 5/7。现在拒绝对非空文本返回空摘录，不确定相关性时保留原文；同一冻结事实集复测为 7/7。
2. 澄清与不支持状态的优先级曾不稳定。现在明确要求排名、趋势等已知未实现算子直接返回不支持；其他任务缺少业务定义时请求澄清。三个原有边界问题全部通过。

早期尝试的失败事实数与状态结果保留在公开汇总中。网络失败、无效计划或验证失败不会触发无上限重试；普通离线检查不访问模型服务。

## 发布边界

此次验收支持将 `compress_planned` 作为可选组件发布，不支持完整语义召回、任意业务理解或报告质量保证。条件和否定提示词只是保守保护措施；没有出现在提示词中的限定仍可能被模型遗漏。近义主题合并、独立语义审阅器、多业务人工金标及固定报告 Skill 的质量评测仍列在[后续路线图](roadmap.md)中。

需要必保的对象、字段和原句应由调用方明确传入。未知字段、数组关系及所有结构化行默认保留；保护内容超过预算时返回失败状态，不能为压缩率继续删减。
